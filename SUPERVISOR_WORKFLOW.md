# Логика работы супервизора и гарантии выполнения шагов

## Общий workflow

### 1. Агент завершает задачу
- Агент помечает задачу как `done`
- Создает finding с результатами
- Отправляет finding в `supervisor_queue`
- **Агент НЕ ждет ревью супервизора - продолжает работать параллельно**

### 2. Супервизор вызывается немедленно
- Когда агент завершает задачу, супервизор вызывается **сразу же** (не ждет завершения всех агентов)
- Супервизор получает finding из `supervisor_queue`
- Супервизор должен обработать finding в **ОДНУ итерацию**

### 3. Обязательные шаги супервизора (гарантированы)

#### Шаг 1: Валидация finding (всегда доступен)
- `read_draft_report` - проверить существующие главы
- `review_agent_progress` - проверить прогресс агента
- **Результат**: Решение - добавить главу или отклонить

#### Шаг 2: Обработка finding (ОБЯЗАТЕЛЬНО)
**Вариант A: Finding валиден**
- **ОБЯЗАТЕЛЬНО**: `write_draft_report` - добавить finding как новую главу
- Задача остается `done`
- **Гарантия**: Если finding валиден, глава ДОЛЖНА быть добавлена

**Вариант B: Finding невалиден (только если TODO операции доступны)**
- `return_task_to_progress` - вернуть задачу в `in_progress`
- Добавить `supervisor_message` с инструкциями
- Задача получает дополнительные шаги (`additional_steps`)
- **Гарантия**: Если finding отклонен, задача возвращается для доработки

#### Шаг 3: Управление задачами (опционально, только если TODO операции доступны)
- `create_agent_todo` - создать новые задачи
- `update_agent_todo` - обновить существующие задачи
- **Гарантия**: Если TODO лимит достигнут, эти операции недоступны, но обработка findings продолжается

### 4. Возврат агента к работе (ГАРАНТИРОВАН)

#### Механизм гарантии возврата
**Цикл `execute_agents` работает в `while` loop:**
```python
while agents_active and iteration_count < max_iterations:
    # Запуск всех агентов параллельно
    # Обработка завершений и вызов супервизора
    # Проверка pending/in_progress задач после цикла
```

**После каждого цикла проверяется:**
- Есть ли у агентов `pending` или `in_progress` задачи
- Если есть → `agents_active = True` → цикл продолжается
- Если нет → `agents_active = False` → цикл останавливается → финализация

#### После успешного добавления главы (finding валиден)
1. Задача остается в статусе `done`
2. **ГАРАНТИЯ**: В следующем цикле `execute_agents`:
   - Система проверяет все задачи всех агентов
   - Если у агента есть `pending` задачи → агент автоматически возьмет следующую
   - Если у агента есть `in_progress` задачи → агент продолжит её
   - Если нет задач → агент вернет `no_tasks`, но цикл продолжается пока есть задачи у других агентов
3. **ГАРАНТИЯ**: Цикл продолжается пока есть задачи → агент гарантированно вернется к работе

#### После отклонения finding (return_task_to_progress)
1. Задача возвращается в статус `in_progress`
2. Задача получает `supervisor_message` с инструкциями
3. Задача получает `additional_steps` для продолжения работы
4. **ГАРАНТИЯ**: В следующем цикле `execute_agents`:
   - Система видит задачу в статусе `in_progress`
   - Агент автоматически продолжает работу над ЭТОЙ же задачей
   - Агент видит `supervisor_message` и отвечает на него
   - Цикл продолжается (`agents_active = True`) пока задача не завершена
5. **ГАРАНТИЯ**: Агент автоматически продолжит работу над возвращенной задачей

#### Критическая проверка после каждого цикла
```python
# После каждого цикла проверяется:
if agents_with_pending_tasks:
    agents_active = True  # Цикл продолжается
    # Агенты автоматически возьмут свои задачи в следующем цикле
else:
    agents_active = False  # Цикл останавливается
    # Вызывается финализация
```

**ГАРАНТИЯ**: Если у агента есть задачи (`pending` или `in_progress`), цикл продолжается и агент автоматически вернется к работе.

- ✅ **Приоритет in_progress**: Если есть `in_progress` задача, агент продолжает её
- ✅ **Автоматический переход**: Если задача `done` и есть `pending`, агент берет следующую
- ✅ **Проверка после ревью**: После ревью супервизора система проверяет, есть ли новые задачи

## Потенциальные проблемы и их решения

### Проблема 1: Агент не возвращается к работе после ревью
**Решение**: 
- Агенты работают параллельно и не ждут ревью
- В следующем цикле агент автоматически проверит свои задачи
- Если есть `pending` или `in_progress` задачи, агент продолжит работу

### Проблема 2: Супервизор не добавляет главу
**Решение**:
- Система отслеживает `findings_without_chapters`
- Супервизор получает urgent reminder в промпте
- Логируется ошибка, если finding не обработан
- В конце работы проверяется, все ли findings обработаны

### Проблема 3: Finding отклонен, но агент не продолжает работу
**Решение**:
- Задача возвращается в `in_progress` с `supervisor_message`
- В следующем цикле агент видит задачу в `in_progress` и продолжает её
- Агент видит `supervisor_message` и отвечает на него
