# Исправление проблемы с множественными in_progress задачами

## Проблема
У агента 3 было 2 задачи в статусе `in_progress`, что нарушает правило "один агент = одна задача за раз".

## Причины проблемы
1. **Race condition**: Супервизор может через `update_agent_todo` установить статус `in_progress` для задачи, когда у агента уже есть другая `in_progress` задача
2. **Отсутствие проверки**: При установке статуса `in_progress` не проверялось, есть ли уже другие `in_progress` задачи
3. **Параллельное выполнение**: Агенты работают параллельно, и супервизор может обновлять задачи одновременно

## Исправления

### 1. Автоматическое исправление в начале работы агента
**Файл**: `backend/src/workflow/research/researcher.py` (строки 339-395)

Если обнаружено несколько `in_progress` задач:
- Автоматически оставляется первая задача в `in_progress`
- Остальные задачи возвращаются в статус `pending`
- Логируется ошибка и исправление
- Если автоматическое исправление не сработало, выполняется ручное исправление

### 2. Защита в `update_agent_todo` (супервизор)
**Файл**: `backend/src/workflow/research/supervisor_agent.py` (строки 1392-1393)

Перед установкой статуса `in_progress`:
- Проверяется, есть ли уже другие `in_progress` задачи
- Если есть → статус НЕ меняется, логируется ошибка
- Защита от создания множественных `in_progress` задач

### 3. Защита в `agent_file_service.update_agent_todo`
**Файл**: `backend/src/memory/agent_file_service.py` (строки 168-169)

Перед установкой статуса `in_progress`:
- Проверяется, есть ли уже другие `in_progress` задачи
- Если есть → статус НЕ меняется, логируется ошибка
- Базовая защита на уровне сервиса

### 4. Дополнительная проверка перед взятием новой задачи
**Файл**: `backend/src/workflow/research/researcher.py` (строки 431-486)

Перед тем как агент берет новую `pending` задачу:
- Перезагружаются todos для получения актуального состояния
- Проверяется, нет ли уже `in_progress` задач
- Если есть → агент продолжает существующую задачу вместо взятия новой
- Защита от race conditions

## Гарантии

### После исправлений:
1. ✅ **Максимум 1 in_progress задача**: Агент всегда работает только над одной задачей
2. ✅ **Автоматическое исправление**: Если обнаружено несколько `in_progress` задач, они автоматически исправляются
3. ✅ **Защита от race conditions**: Проверки на всех уровнях (агент, супервизор, сервис)
4. ✅ **Последовательное выполнение**: Задачи выполняются по порядку:
   - Агент завершает задачу → помечает как `done` → создает finding
   - Супервизор ревьюит finding:
     - Если глава добавлена → задача остается `done` → агент берет следующую `pending` задачу
     - Если задача возвращена → задача становится `in_progress` → агент продолжает эту задачу

## Логирование

Все критические действия логируются:
- Обнаружение множественных `in_progress` задач
- Автоматическое исправление
- Попытки установить статус `in_progress` когда уже есть другая задача
- Переход к следующей задаче после завершения

## Проверка

После перезапуска системы:
1. У каждого агента должна быть максимум 1 задача в статусе `in_progress`
2. Если обнаружено несколько `in_progress` задач, они автоматически исправляются
3. Задачи выполняются последовательно, а не параллельно
